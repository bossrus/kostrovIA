Как устроена CRM «Объекты и задачи»

Для каждой стройки есть карточка с названием, адресом и списком задач. Постановщик создаёт свои объекты, описывает работу и назначает исполнителей. Исполнитель видит порученные ему задачи, берёт их в работу и отправляет результат на проверку. Постановщик принимает результат либо возвращает задачу с обязательным объяснением, что исправить. После исправления задача проходит проверку заново.

В карточке задачи сохраняется история: кто и когда изменил статус, какое состояние было раньше, какое стало и что написал участник. Автор и время события определяются системой. Пользователь не может переписать историю задним числом.

Доступ ограничен на стороне хранилища данных. Это означает, что скрытие кнопок — только удобство интерфейса: даже если попытаться отправить команду напрямую, сервер повторно проверит полномочия. Постановщик видит только свои объекты. Исполнитель видит только собственные задачи и связанные с ними стройки; чужие задачи в той же стройке ему не открываются. Он не может назначать людей, менять описание задания, принимать работу, удалять объекты или повышать свои права.

Один сотрудник может совмещать обе роли: управлять собственными объектами и выполнять задачи, назначенные другим постановщиком. Такие права складываются только для доступных ему записей. Изменять задачу и исполнителя можно до начала работы. После этого содержание поручения фиксируется.

Новые аккаунты создаёт администратор, самостоятельная регистрация выключена. Удаление убирает запись из рабочего интерфейса, сохраняя историю в базе. Стройку с неудалёнными задачами удалить нельзя. Таким образом, команда видит актуальную работу, а важные сведения о принятых решениях не теряются.
