Проверки 5 ноября 2026 года после уточнений заказчика

`npm run build` — строгая проверка TypeScript и production-сборка Vite проходят.

`npm run test:db` — **330 успешных локальных проверок** в изолированном PostgreSQL через PGlite. Все четыре SQL-миграции выполняются без подмены прикладных функций, триггеров, grants и RLS. Supabase Auth заменён минимальной схемой `auth.users` и функцией чтения тестового UUID сессии.

Проверены:

- Миграция старой demo с совмещённой ролью, включая переназначение принятой задачи без изменения статуса, автора, объекта, даты и истории; увеличение версии.
- Полный откат миграции при неизвестном смешанном профиле и успешная чистая установка с `seed.sql`.
- Ограничение ровно одной роли в базе, общий доступ обоих постановщиков, редактирование объекта коллеги, создание задачи в его объекте и удаление его записей.
- Правки содержания и переназначения обоими постановщиками во всех пяти статусах; сохранение статуса; запреты исполнителю во всех статусах.
- Немедленная потеря доступа прежним исполнителем к задаче и истории, запрет действий из устаревшего интерфейса, доступ нового исполнителя.
- Видимость имени владельца объекта исполнителю, чью задачу создал другой постановщик.
- Матрица переходов для четырёх пользователей и соответствие кнопок `actions()` этим правилам, полный цикл с доработкой, обязательный комментарий, неизменяемая история.
- Отказ при устаревших версиях правки, удаления и перехода, запрет переноса между объектами, прямой записи в таблицы, повышения роли и анонимного доступа.

`node --check scripts/demo-seed.mjs` и `node --check scripts/security-test.mjs` проходят. `git diff --check` не находит ошибок пробелов.

`npm run test:security` — **284 успешные проверки настоящего Supabase API** после применения миграций 003 и 004 через SQL Editor. Первые две миграции уже действовали; это проверено перед обновлением схемы. Использованы публичный ключ и четыре обычные пользовательские сессии. Проверены общий доступ постановщиков, единственные роли, редактирование и переназначение во всех статусах, граф переходов, история, права исполнителей, устаревшие версии и параллельный старт. Временные тестовые задачи и объект логически удалены штатными RPC.

Облачный набор дополнительно проверяет закрытую регистрацию и поведение PostgREST. Подробный лог находится в игнорируемом файле `test-results/security.log`. Для проверки продакшена после публикации откройте список объектов: внизу каждой карточки должны быть подпись «Постановщик» и его имя. Netlify собирает приложение из ветки `main` репозитория GitHub.
