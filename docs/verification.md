Проверки 5 ноября 2026 года

`npm run build` — строгая проверка TypeScript и production-сборка Vite проходят. Зависимости Supabase и React вынесены в отдельные кешируемые части сборки.

`npm run test:security` — **164 успешные проверки настоящего Supabase API**. Использовался публичный publishable key и четыре независимые пользовательские сессии. Административный ключ не использовался.

Проверены изоляция объектов разных постановщиков, личные задачи двух исполнителей, совмещение ролей, видимость истории, анонимный доступ, закрытая регистрация, изменение роли и прямые записи в таблицы. Полная матрица запрещённых переходов проверена для четырёх пользователей в каждом состоянии рабочего цикла. Пройдены весь цикл с доработкой, обязательный комментарий, запрет редактирования после старта, отклонение устаревшей версии и одновременный старт двумя запросами.

При проверке обнаружено, что SQLSTATE `40001` для конфликта версии вызывает повторные попытки в используемой версии PostgREST. Конфликт заменён на `PT409` с HTTP 409; изменение включено в миграции. После исправления весь набор проверок прошёл. Обоснование: [официальная база знаний Supabase](https://supabase.com/kb/troubleshooting/high-cpu-and-infinite-transaction-retries-when-using-custom-error-codes-in-rpc-functions).

Локальные подробные логи сохраняются в `test-results/security.log` и не попадают в Git. Тестовые записи логически удалены, их аудит сохранён согласно принятой модели удаления.

В браузере проверены вход и выход, смена аккаунта, создание объекта и задачи, редактирование новой задачи, старт исполнителем, отправка на проверку, обязательность причины возврата и отображение комментариев в истории. У исполнителя отсутствуют кнопки редактирования, удаления и приёма работы. Дополнительно проверено, что удаление объекта скрыто при наличии задач и появляется после удаления последней задачи.
